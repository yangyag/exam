# front/ — 정보처리기사 필기 학습 앱 (Nuxt 4 + Tailwind CSS)

`back/` 의 FastAPI(`http://127.0.0.1:8092`)를 호출해 아래 화면을 제공합니다.

- **홈**(`/`) — 과목 5개·사이클 진행 상황 + 회차별 연습·모의고사 진입점과 진행 중인 회차 세션 (헤더에 `이전 결과` 진입)
- **연습 화면**(`/sessions/{sessionId}`) — 문항 풀이 → 제출 → 해설 → 다음 문항 (과목 사이클 라운드·회차별 연습)
- **회차 선택**(`/exams`) — 13회차 목록에서 회차별 연습·모의고사를 고르고 이어서 풀기
- **모의고사**(`/exam/{sessionId}`) — 정답 비공개 풀이 → 최종 제출 → 결과·문항별 해설
- **이전 결과**(`/history`) — 과목별 최근 사이클(상태·라운드별 문항/정답·시각, 진행 중이면 이어서 풀기) + 회차 세션(응답/문항·제출 시각·합격 여부)

문항 화면(연습·모의고사)의 문항 헤더에는 **`복사` 버튼**(`QuestionCopyButton.vue`)이 있습니다 — 문제 문장·지문(코드·표·본문)·보기 4개를 화면에 보이는 순서대로 클립보드에 넣고 버튼 옆에 잠깐 `복사됨` 을 표시합니다. **정답·해설·보기별 해설은 복사하지 않습니다**(모의고사 진행 중 정답 비노출 규칙과 같습니다). 그림이 있는 문항은 텍스트만 복사하면 뜻이 달라지므로 복사하지 않고 `그림이 있는 문항은 복사할 수 없습니다.` 안내만 보여줍니다.

## 실행

```bash
cd front
npm install
npm run dev        # http://localhost:8091 (SPA)
```

백엔드가 먼저 떠 있어야 합니다(없으면 홈이 기동 명령을 안내합니다):

```bash
cd back && .venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8092
```

- **포트 8091 · 주소는 `http://localhost:8091`** — 백엔드 기본 CORS 허용 오리진이 이 값입니다(`back/README.md` 6장).
  `127.0.0.1:8091` 은 오리진 문자열이 달라 CORS 에 막힙니다.
- API 오리진은 `NUXT_PUBLIC_API_BASE`(기본 `http://127.0.0.1:8092`)로 바꿉니다.
- `ssr: false`(SPA) 이고 다크모드 대응은 없습니다(흰 배경 고정 — `AGENTS.md` 자료 처리 정책).

## 스크립트

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버(8091) |
| `npm run build` | 타입 검사(`nuxt typecheck`) + 프로덕션 빌드. **타입 오류가 있으면 실패합니다** |
| `npm run typecheck` | 타입 검사만 (`vue-tsc`) |
| `npm run gen:types` | `app/types/api.gen.ts` 재생성 — 백엔드 `/openapi.json` 에서 뽑습니다(백엔드가 떠 있어야 함). 산출물은 커밋합니다 |
| `npm run shots` | Playwright 스크린샷 + 화면 점검. dev 서버가 없으면 자동 기동·종료하고 `<저장소 루트>/tmp/shots/` 에 저장(gitignore). `SHOTS_ONLY=<단계>` 로 단계 선택 — 이름은 `real-data`·`states`·`backend-down`·`loading`·`empty`·`practice`·`practice-conflicts`·`exams-list`·`exam-taking`·`exam-closed`·`history`·`copy-button`·`hover` 이고, 모르는 이름(오타)이나 쉼표·공백만 있는 값이면 사용 가능한 목록을 찍고 **exit 1** 로 멈춥니다(0단계 조용한 통과 없음). **`SHOTS_ONLY=`(완전히 빈 값)는 변수를 주지 않은 것으로 보고 전체 13단계를 돌립니다**(무엇을 했는지 로그에도 남깁니다). 대조군은 `SHOTS_FAULT=states`(그 단계 화면에 콘솔 오류·JS 예외를 일부러 심음) · `SHOTS_HOVER_FREEZE=all\|color\|block`, 실행 끝에 `단계 N개 실행 · 스크린샷 M컷` 요약과 실패로 세지 않은 콘솔 로그 건수를 남깁니다 |

`npm run shots` 가 확인하는 것:

- 실제 DB 데이터로 홈·회차 선택 화면 렌더링 — 과목 5개, 과목별 고유 문항 176·194·194·199·181(합계 944 — 과목마다 중복을 제거한 수의 합계이고,
  전역 내용키 그룹 수 938 과는 다른 기준이다), 헤더의 기준 표기, 회차 13행(제목·문항 수).
  **카드의 진행도(`n / m`)·정답 수·정답 패널 라벨·보조 줄은 `GET /api/subject-cycles/overview` 응답에서 기대값을 유도해 화면 값과 맞춘다 —
  사용자 진행 기록이 있어도 통과한다**(`0 / N`·정답 `0` 을 가정하지 않는다). 값이 아예 그려지지 않거나 API 와 다르면 실패한다.
- 브라우저 콘솔 오류 0, 가로 잘림 0, 클릭 영역(`data-tap` 요소) 44px 이상.
  **콘솔 오류는 모든 단계에서 판정합니다**(`scripts/shots.mjs` 의 `judgeConsoleErrors` 한 곳) — 대체 API 가 일부러 409·404 로 답하는 화면은 그 네트워크 로그만 봐주고(몇 건을 봐줬는지 통과 줄에 함께 찍습니다) JS 예외(`pageerror`)와 그 밖의 콘솔 오류는 실패입니다.
  요청을 끊거나 4xx 로 답하는 것이 그 화면의 주제인 경우(`backend-down`·`practice-conflicts`)와 hover 단계의 부수 요청만 `noteIgnoredConsoleErrors` 로 **사유·실제 메시지·건수를 남기고** 봐주되, **JS 예외는 그 화면에서도 실패**입니다.
  오류를 모아 두고 단언하지 않는 단계는 없습니다 — [2] 상태 4종이 그렇게 새고 있었고(수집한 오류를 그대로 버림) 지금은 네트워크 로그 외에는 그대로 실패로 끝납니다. 실행 끝 요약에 `콘솔 로그 N건은 의도된 경로로 보고 실패로 세지 않았습니다` 로 총계를 남깁니다.
- 상태별 동작이 보내는 본문 — 시작하기 `{subjectCode, replaceActive:false}` / 새로 구성 `{subjectCode, replaceActive:true}`(확인 대화상자를 거침), 409(이미 진행 중) 안내 문구
- 상태 4종·확인 대화상자·백엔드 다운·로딩·빈 목록 화면 — 이 컷들은 **브라우저에서 API 응답을 대체**해 찍습니다(실제 요청을 차단하므로 DB 는 그대로).
- 연습 화면 — 코드·지문·표·도식 네 종류를 지나가며 문항·해설·라운드 종료·오답 복습 라운드·사이클 완료를 캡처한다.
  **보기 선택(방향키)과 제출(Enter)이 키보드만으로 되는지**, **보기별 해설이 정답이면 접힘 유지·오답이면 자동 펼침**이고
  그 뒤에도 직접 접기·다시 펼치기가 되는지(복습 라운드 오답 포함), 라운드 종료 집계 값,
  409(다른 보기 재제출)·중단 세션·빈 라운드·404 안내도 확인한다. 이 컷도 API 대체이며 픽스처는 실제 데이터셋 문항(`scripts/practice-fixtures.mjs`)이다.
- 복사 버튼 — 클립보드 권한을 준 컨텍스트에서 **`navigator.clipboard.readText()` 로 실제 담긴 문자열을 읽어** 판정한다:
  코드 문항은 문제·코드·보기 4개가 들어가고(키보드 Tab·Enter 로도 동작), 표 문항은 표 지문까지 들어가며,
  **어느 경우에도 정답·해설·보기별 해설은 들어가지 않는다**(모의고사는 제출 전 상태로 확인).
  도식 문항은 안내 문구가 뜨고 **클립보드가 앞 복사본 그대로**인지 본다(`scripts/practice-fixtures.mjs`·`exam-fixtures.mjs`).
- 마우스오버 반응 — 화면 13상태(홈 4종·홈 실데이터·회차 선택·연습 3종·모의고사 4종·이전 결과)에서 **보이는 클릭 요소를 하나씩
  실제 마우스로 올려** **배경색·글자색·테두리색 중 하나라도 계산값이 바뀌는지** 본다. 그림자·이동·투명도만 바뀌는 요소는
  **실패로 기록하고 어떤 속성만 바뀌었는지 요소마다 남긴다**(예: `색(배경·글자·테두리) 변화 없이 그림자·이동만 바뀜(boxShadow, transform)`) —
  그림자·1px 이동만으로는 hover 가 있는지 알 수 없어(사용자 신고: `이전 결과`는 반응이 있고 `새로고침`은 없음) **색 변화가 통과 조건**이다.
  클릭할 수 없는 요소(`disabled` 속성·`disabled` 필드셋 안·`pointer-events:none`·`aria-disabled`)·숨김 요소는 제외하되
  **개수와 사유를 요소마다 계속 남긴다**(조용히 빼지 않는다). **비활성 요소에 hover 가 붙지 않는 것 자체는 이 점검이 아니라
  `app/assets/css/main.css` 의 클릭 요소 공통 규칙이 보장한다**(`:disabled`·`disabled` 필드셋 안·`.pointer-events-none`·`[aria-disabled="true"]` 를 제외하고,
  버튼 hover 색은 `not-disabled:` 접두로만 켠다) — 점검은 그런 요소를 대상에서 빼고 사유만 남기므로, 비활성 가드는 CSS 를 보고 확인한다.
  떠오름(그림자 + 1px)은 같은 공통 규칙 한 곳에서, 색·테두리는 화면·컴포넌트별로 얹는다.
- hover 점검 대조군 — `SHOTS_HOVER_FREEZE=all`(판정값 전부)·`color`(색만)은 클릭 요소의 hover 를 인라인 `!important` 로 못박고, `block` 은 화면 전체를 투명한 덮개로 막아 마우스가 닿지 않게 한다.
  이때 점검이 **모든 요소를 실패로 잡아야** 헛통과가 없다고 본다(`SHOTS_ONLY=hover` 로 이 단계만 빠르게 돌릴 수 있다).
  **마우스를 올려 보지 못한 요소(unreached)도 실패로 센다** — '확인하지 못했다' 를 통과로 넘기면 점검이 못 돈 화면이 초록에 섞이므로, 통과 문구(`클릭 요소 N개 모두 …`)도 전 요소를 실제로 확인했을 때만 찍는다(`block` 대조군은 화면마다 `N/N개` 점검 불가로 실패해야 정상).
- 회차 선택·모의고사 — 회차 13행·이어풀기 표시·시작 본문(`{mode, examId, replaceActive:false}`)·409 중단 확인 대화상자,
  모의고사 풀이(**풀이 중 정답·해설 문장이 화면에 없는지**·이어풀기 13번 위치·번호 그리드 100칸의 선택/미응답 구분),
  선택 즉시 저장(`{choiceNo}` 만 — 정답·시간 없음)·선택 해제(`choiceNo:null`), **방향키로 문항 이동·보기 선택**,
  미응답 수를 강조한 제출 확인 대화상자, 결과 요약(평균·합격 여부·과목별 40점 기준)과 문항 그리드(정답/오답/미응답),
  번호 클릭 후 해설 재조회(**조회는 PUT 을 보내지 않음**), 중단·비-exam·404·제출 409 안내를 확인한다(API 대체, `scripts/exam-fixtures.mjs`).
- 이전 결과 화면(`/history`) — 사이클 상태 3종(완료·진행 중·중단)과 라운드별 문항/정답 수, 진행 중 사이클의 이어서 풀기 경로,
  회차 세션 목록이 회차(`examId`) 있는 모의고사·회차별 연습만 담는지, 합격/불합격 배지와 `examResult` 를 조회한 세션 범위,
  모의고사·연습 화면으로 가는 경로, 빈 상태 안내를 대체 응답으로 확인한다(`scripts/history-fixtures.mjs`).
  **실 DB 로도 한 번** 홈 헤더의 `이전 결과` 링크를 눌러 들어가서, 화면 값(상태 배지·라운드 수·이어서 풀기·회차 세션 수)이
  같은 API 응답과 일치하는지까지 본다(전부 조회라 진도 테이블은 그대로다).

## 홈 화면 계약

`GET /api/subject-cycles/overview` 가 주는 4가지 상태를 그대로 씁니다(`back/README.md`).

| 상태 | 카드 표시 | 동작 |
|---|---|---|
| `not_started` | 시작 전 · `0 / 고유문항` · 정답 0 | **시작하기** → `POST /api/subject-cycles` |
| `first_pass` | 전체 풀이 중 · 1라운드 진행도·정답 수 | **이어서 풀기**(열린 라운드 세션으로 이동) · **새로 구성**(확인 후 `replaceActive=true`) |
| `reviewing` | 오답 복습 중 · 라운드 진행도 + 1차 풀이 요약 | 위와 같음 |
| `completed` | 완료 · 1차(전체) 풀이 정답 수 | **새로 구성** |

- 정답 패널 라벨은 상태에 따라 다릅니다 — 시작 전 `정답 수`, 1차 풀이 `1차 정답`, 복습 라운드 `복습 정답`, 완료 `1차 정답`
  (완료 카드는 보조 줄에 `1차(전체) 풀이 정답 176/194 · 완료일 …` 을 함께 보여 줍니다).
- 진행도 분모는 그 라운드의 문항 수이고, 카드의 "고유 문항 N개" 는 과목의 중복 제거 문항 수입니다(라운드와 다르면 "이번 라운드 N문항"을 덧붙입니다).
  헤더의 합계(944)는 **과목별 고유 문항 수의 합**이고, 데이터셋 전체 내용키 그룹 수 **938**(두 과목에 걸친 그룹 6개)과는 기준이 다릅니다.
- 회차별 연습·모의고사 진입 — 홈 아래쪽 **회차별 연습 · 모의고사** 자리에 13회차 안내와 `회차 선택`(`/exams`) 링크를 두고,
  `GET /api/sessions?limit=200` 목록을 훑어 **`examId` 가 있는 열린 세션**(`finishedAt` 이 null)을 회차 제목·문항 수와 함께
  카드로 보여줍니다(모의고사=`/exam/{id}`, 회차 연습=`/sessions/{id}` 로 이동). 새로 시작은 회차 선택 화면에서 합니다.
  회차 조회가 실패하면 과목 카드는 그대로 두고 이 자리에서만 다시 시도를 안내합니다(기본안 — 백엔드 필터 추가는 이번 범위가 아님).
- 헤더에 **이전 결과**(`/history`) 링크를 둡니다 — 지난 사이클과 회차 세션 기록은 그 화면에서 봅니다(아래 "이전 결과 화면 계약").

## 연습 화면 계약

`/sessions/{sessionId}` 는 과목 사이클 라운드(`subject`·`review`)와 회차별 연습(`exam_practice`)을 푸는 화면입니다
(모의고사 `exam`·랜덤 `random` 은 이 화면이 아니라고 안내합니다). 흐름은 설계 3.1절 그대로입니다 —
문항·보기 → 보기 선택 → 제출 → **같은 화면에 정오답·해설** → 다음 문항.

- **진행 위치는 서버가 정합니다.** 세션 조회의 `nextSeq` 로 그 문항(`GET …/items/{seq}`)을 열기 때문에
  새로고침·재접속·기기 변경 후에도 같은 자리로 복원됩니다. 헤더는 데스크톱에서 `과목 · 라운드 · 문항 n / m` + `남은 N문항` 을 한 줄로 보여주고,
  375px 처럼 좁은 화면에서는 **`문항 n / m` 을 앞세워 잘리지 않게 두고** 과목·라운드를 아랫줄로 내립니다(리뷰 P2-1).
  이어풀기로 복원했을 때는 "이어서 풀기 — n / m 문항을 마쳤습니다" 안내를 한 번 띄웁니다(홈의 '이어서 풀기'도 같은 세션으로 들어옵니다).
- **지문은 종류별로 다르게 그립니다** — `code`(고정폭·들여쓰기 보존)·`table`(행/열 구분이 보이게 고정폭)·`text`(문단).
  `figure.needed` 문항은 `/figures/...` 이미지를 `alt` 캡션과 함께 보여줍니다(경로는 API 오리진 기준 상대경로).
- **보기별 해설은 오답일 때 자동으로 펼쳐진다(설계 9.1절 2-b).** 정오답 배지·정답 번호·전체 해설·핵심 개념을 먼저 보여주고,
  보기별 해설은 제출 결과가 **오답이면 펼친 상태**로, **정답이면 접힌 상태**로 시작합니다(복습 라운드도 같습니다).
  상태는 제출 응답(`isCorrect`)과 채점된 슬롯을 다시 열 때의 `result` 로 정하므로, 문항을 옮겼다가 되돌아와도 그 슬롯의 정오답에 맞습니다.
  자동 펼침 뒤에도 `보기별 해설 4개 접기` 버튼으로 직접 접고 펼칠 수 있습니다 — 펼치면 **4개 보기 전부**(정답 보기 포함)의
  보기 텍스트와 정오답 이유를 보여주고 내가 고른 보기에 표시를 붙입니다.
- **제출 응답을 그대로 씁니다** — `PUT …/items/{seq}/answer` 의 `isCorrect`·`answer`·`explanation`·`choicesAnalysis`,
  그리고 진행(`session.nextSeq`)·라운드 종료(`roundResult`)·다음 라운드(`cycle`)를 화면 상태로 삼습니다.
  `elapsedMs` 는 문항이 뜬 뒤 제출까지의 시간입니다.
- **409 는 안내로 끝내고 진행을 막지 않습니다.** 이미 채점된 슬롯에 다른 보기를 보내면 서버 메시지를 그대로 보여주고
  저장된 채점 결과를 다시 불러와 다음 문항으로 갈 수 있게 합니다. 중단(`abandoned`)·종료 세션은 안내와 함께 홈으로 돌려보냅니다.
  같은 보기 재전송은 서버가 멱등(`200`)이라 네트워크 오류 뒤 그대로 다시 눌러도 기록이 늘지 않습니다.
- **라운드 종료** — 마지막 문항을 채점하면 `roundResult`(전체·정답·오답)로 결과를 요약하고,
  `cycle.nextSessionId` 가 있으면 오답 복습 라운드로 들어가는 버튼을, 없으면(오답 0 = 사이클 완료) 완료 안내와 홈 이동을 보여줍니다.
- **오류 상태** — 로딩 스켈레톤, 네트워크·서버 오류(다시 시도·홈으로, 백엔드가 꺼져 있으면 홈과 같은 기동 명령 안내),
  404(없는 세션·문항), 빈 라운드(문항 0개) 안내를 따로 그립니다.
- 모의고사(`exam`) 세션을 이 경로로 열면 모의고사 화면(`/exam/{id}`)으로 가는 링크와 함께 안내합니다.

## 회차 선택 화면 계약 (`/exams`)

- `GET /api/exams` 의 13회차를 연도·회차 내림차순으로 보여줍니다(제목·문항 수·도식 수). 회차마다 **회차별 연습**·**모의고사** 버튼이 있습니다.
- 시작: `POST /api/sessions {mode:'exam_practice'|'exam', examId, replaceActive:false}` → 201 → 회차별 연습은 기존 연습 화면 `/sessions/{id}`,
  모의고사는 모의고사 화면 `/exam/{id}` 로 이동합니다(문항은 번호순 100개).
- 그 회차·방식에 진행 중인 세션이 있으면 행 안에 `이어서 풀기` 를 함께 보여줍니다(`GET /api/sessions?limit=200` 을 훑어 `examId` 가 있는 열린 세션만 추림).
- 409(이미 진행 중)는 확인 대화상자를 띄우고 **중단하고 새로 시작** 을 누르면 `replaceActive:true` 로 다시 보냅니다(이전 세션은 `abandoned`).
  400·404 는 화면 아래 안내 문구로 알립니다.

## 모의고사 화면 계약 (`/exam/{sessionId}`)

- **풀이 중에는 정답·해설이 화면에 없습니다.** 조회 응답에도 정답·해설이 실리지 않고(제출 전 `result` 는 null), 화면도 그리지 않습니다.
- **보기를 고르면 즉시 저장**합니다 — `PUT /api/sessions/{id}/items/{seq}/answer {choiceNo}` → 200 `{seq, choiceNo, answeredAt}`(정답 없음).
  같은 문항의 보기를 다시 고르면 덮어쓰고, **선택 해제** 는 `choiceNo:null` 입니다(해제하면 다시 미응답으로 돌아갑니다).
  화면에 먼저 반영하고 실패하면 서버 값으로 되돌린 뒤 재시도를 안내합니다. 저장 상태(저장 중·저장했습니다 시각·실패)는 문항 위 줄에 표시합니다.
- **이어풀기 위치는 서버 `nextSeq`**(선택하지 않은 가장 작은 번호)이고, 진행률·미응답 수는 슬롯 목록의 `choiceNo` 로 셉니다.
- **번호 그리드(기본안)** — 100문항을 원으로 그립니다. **미응답은 빈 점선 원, 선택됨은 채운 파란 원**, 지금 보는 문항은 검은 링.
  데스크톱은 10열로 펼쳐 두고, 375px 에서는 세로로 길어(6열) **기본 접힘**입니다 — 제목 줄의 `선택 N · 미응답 M` 을 누르면 펼쳐집니다.
  번호를 누르면 그 문항으로 이동하고, 방향키(←→↑↓·Home·End)로도 옮길 수 있습니다. 그리드는 탭 정지 1개(로빙 tabindex)라
  키보드만으로 보기 선택(라디오 방향키)과 문항 이동이 됩니다.
- **제출 확인** — 제출 버튼은 확인 대화상자를 띄우고 **미응답 문항 수를 큰 숫자로 강조**합니다(미응답이 없으면 그 사실을 알립니다).
  `POST /api/sessions/{id}/submit` 은 한 번만 반영되고 재전송해도 같은 결과가 옵니다(멱등) — 네트워크 오류 뒤 다시 눌러도 안전합니다.
  409(중단)·400(비-exam)은 안내 화면으로 돌리고 회차 목록·홈으로 보냅니다.
- **결과 화면(기본안: 요약 + 그리드 + 문항별 해설 재조회)** — 제출하면 같은 페이지가 결과로 바뀌고, 이미 제출한 세션을 다시 열어도 결과가 바로 나옵니다.
  ① 요약 — 평균 점수·합격 여부(매 과목 40점 이상 + 전 과목 평균 60점 이상)·전체/응답/미응답/정답/오답(오답은 미응답 제외)
  ② 과목별 점수 5행 — 정답 수·점수·40점 기준 통과 여부 ③ 문항 그리드 — **정답 초록 · 오답 빨강 · 미응답 빈 점선 원**
  ③ 번호를 고르면 `GET …/items/{seq}` 의 `result` 로 문항·정답·내 답·전체 해설·핵심 개념·보기별 해설(접힘)을 보여줍니다.
  해설 조회는 GET 뿐이라 원장(`study_attempt`)을 늘리지 않습니다. 세션 재조회가 실패하면 그리드에 안내와 다시 불러오기를 띄웁니다.
- **오류·안내** — 로딩 스켈레톤, 네트워크·서버 오류(다시 시도·회차 목록), 중단된 모의고사·모의고사가 아닌 세션 안내(연습 화면 링크), 없는 세션 404.
  제출이 409(중단)·400(비-exam)로 끝날 때도 같은 안내 화면으로 가며, **제목은 서버가 준 사유와 일치**합니다
  (세션의 `endReason` 만 보면 제출 409 때 낡은 값이라 사유를 안내 상태에 함께 담습니다).

## 이전 결과 화면 계약 (`/history`)

설계 9.1절 7-a — 과목별 최근 사이클과 회차 세션 기록을 한 화면에서 봅니다. **조회(GET)만 쓰는 화면**이라
이 화면을 열어도 진도 테이블(`study_attempt`·`study_state`)에 아무것도 쓰지 않습니다.

- ① **과목별 최근 사이클** — 과목 5행 고정. 과목마다 `GET /api/subject-cycles?subjectCode=N&limit=1`(최근 생성순이라 1건이 마지막 사이클)로
  마지막 사이클을 받아 상태 배지(**진행 중 · 완료 · 중단**)·사이클 시작/종료 시각·라운드 목록을 보여줍니다.
  라운드 줄에는 라운드 번호·모드(전체 문항 풀이/오답 복습)·마무리 상태(진행 중/완료/중단)·`푼 문항 n / m · 정답 k`·진행 막대·시작/종료 시각이 들어갑니다
  (집계는 서버의 슬롯 기준 값 `itemCount`·`answered`·`correct` 를 그대로 씁니다).
  `status='active'` 이고 끝나지 않은 라운드가 있으면 **이어서 풀기** → `/sessions/{sessionId}`, 사이클이 없으면 "아직 사이클이 없습니다" 안내로 대체합니다.
- ② **회차 세션 — 모의고사 · 회차별 연습** — `GET /api/sessions?limit=50` 에서 **회차(`examId`)가 있는 `exam`·`exam_practice` 세션만** 추려
  회차 제목(`GET /api/exams` 에서 제목·문항 수)·응답/문항·시작 시각과 **제출 시각**(모의고사) 또는 종료 시각(연습)을 보여줍니다.
  상태 배지는 진행 중/제출 완료/완료/중단이고, 각 항목에서 그 세션의 화면으로 갑니다 — 모의고사 `/exam/{id}`, 회차별 연습 `/sessions/{id}`.
  사이클 라운드(`examId` 가 null)와 `random` 세션은 이 목록에 넣지 않습니다.
- **합격 여부는 제출이 끝난 모의고사만** `GET /api/sessions/{id}` 의 `examResult` 로 채웁니다(`합격|불합격 · 평균 n점 · 미응답 n`).
  목록을 먼저 그리고 결과는 도착하는 대로 붙입니다 — 한 건이 실패해도 목록은 그대로 남고, 중단·연습 세션은 조회하지 않습니다.
- **빈 상태** — 사이클도 회차 세션도 없으면 `아직 기록이 없습니다` 안내(홈·회차 선택 링크), 회차 세션만 없으면 그 자리에 "아직 회차 세션이 없습니다" 안내를 씁니다.
  로딩 스켈레톤·오류(다시 시도·홈으로, 백엔드 다운 안내)도 다른 화면과 같은 모양입니다.

검증(2026-09, 실 DB): 한 과목 사이클을 만들어 브라우저로 문항 2개를 제출하고, 새로고침 복원·홈 이어서 풀기·
176문항 라운드 종료(정답 173·오답 3)·오답 복습 라운드(3문항)·사이클 완료까지 확인한 뒤 검증이 만든 진도 행을 지워 0행으로 되돌렸습니다.

검증(2026-09, 실 DB · 모의고사): 2026-1 모의고사를 실제로 만들어 **100문항 중 3문항만 고른 채(미응답 97)** 제출했습니다.
결과 화면에서 미응답 97문항이 오답 3문항과 구분되어 표시되고, 제출 전에는 응답·화면 어디에도 정답·해설이 없으며
(제출 전 `result` null·`isCorrect` null), 제출 확인 대화상자가 미응답 97을 강조하고, 재제출이 같은 본문을 돌려주고(멱등),
세션 재조회가 `examResult` 를 주는 것을 확인했습니다. DB 에서는 슬롯 100행(미응답 97 = `choice_no NULL`·`is_correct false`)에
