# front/ — 정보처리기사 필기 학습 앱 (Nuxt 4 + Tailwind CSS)

`back/` 의 FastAPI(`http://127.0.0.1:8092`)를 호출해 **홈 화면(과목 5개·사이클 진행 상황)** 과
**연습 화면(문항 풀이 → 제출 → 해설 → 다음 문항)** 을 제공합니다.
회차별 연습·모의고사 진입점은 아직 자리만 둡니다.

## 실행

```bash
cd front
npm install
npm run dev        # http://localhost:8091 (SPA)
```

백엔드가 먼저 떠 있어야 합니다(없으면 홈이 기동 명령을 안내합니다):

```bash
cd back && .venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8092
```

- **포트 8091 · 주소는 `http://localhost:8091`** — 백엔드 기본 CORS 허용 오리진이 이 값입니다(`back/README.md` 6장).
  `127.0.0.1:8091` 은 오리진 문자열이 달라 CORS 에 막힙니다.
- API 오리진은 `NUXT_PUBLIC_API_BASE`(기본 `http://127.0.0.1:8092`)로 바꿉니다.
- `ssr: false`(SPA) 이고 다크모드 대응은 없습니다(흰 배경 고정 — `AGENTS.md` 자료 처리 정책).

## 스크립트

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버(8091) |
| `npm run build` | 타입 검사(`nuxt typecheck`) + 프로덕션 빌드. **타입 오류가 있으면 실패합니다** |
| `npm run typecheck` | 타입 검사만 (`vue-tsc`) |
| `npm run gen:types` | `app/types/api.gen.ts` 재생성 — 백엔드 `/openapi.json` 에서 뽑습니다(백엔드가 떠 있어야 함). 산출물은 커밋합니다 |
| `npm run shots` | Playwright 스크린샷 + 화면 점검. dev 서버가 없으면 자동 기동·종료하고 `<저장소 루트>/tmp/shots/` 에 저장(gitignore) |

`npm run shots` 가 확인하는 것:

- 실제 DB 데이터로 홈 렌더링 — 과목 5개, 과목별 고유 문항 176·194·194·199·181(합계 944 — 과목마다 중복을 제거한 수의 합계이고,
  전역 내용키 그룹 수 938 과는 다른 기준이다), 헤더의 기준 표기
- 브라우저 콘솔 오류 0, 가로 잘림 0, 클릭 영역(`data-tap` 요소) 44px 이상
- 상태별 동작이 보내는 본문 — 시작하기 `{subjectCode, replaceActive:false}` / 새로 구성 `{subjectCode, replaceActive:true}`(확인 대화상자를 거침), 409(이미 진행 중) 안내 문구
- 상태 4종·확인 대화상자·백엔드 다운·로딩·빈 목록 화면 — 이 컷들은 **브라우저에서 API 응답을 대체**해 찍습니다(실제 요청을 차단하므로 DB 는 그대로).
- 연습 화면 — 코드·지문·표·도식 네 종류를 지나가며 문항·해설·라운드 종료·오답 복습 라운드·사이클 완료를 캡처한다.
  **보기 선택(방향키)과 제출(Enter)이 키보드만으로 되는지**, 보기별 해설 기본 접힘→펼치기, 라운드 종료 집계 값,
  409(다른 보기 재제출)·중단 세션·빈 라운드·404 안내도 확인한다. 이 컷도 API 대체이며 픽스처는 실제 데이터셋 문항(`scripts/practice-fixtures.mjs`)이다.

## 홈 화면 계약

`GET /api/subject-cycles/overview` 가 주는 4가지 상태를 그대로 씁니다(`back/README.md`).

| 상태 | 카드 표시 | 동작 |
|---|---|---|
| `not_started` | 시작 전 · `0 / 고유문항` · 정답 0 | **시작하기** → `POST /api/subject-cycles` |
| `first_pass` | 전체 풀이 중 · 1라운드 진행도·정답 수 | **이어서 풀기**(열린 라운드 세션으로 이동) · **새로 구성**(확인 후 `replaceActive=true`) |
| `reviewing` | 오답 복습 중 · 라운드 진행도 + 1차 풀이 요약 | 위와 같음 |
| `completed` | 완료 · 1차(전체) 풀이 정답 수 | **새로 구성** |

- 정답 패널 라벨은 상태에 따라 다릅니다 — 시작 전 `정답 수`, 1차 풀이 `1차 정답`, 복습 라운드 `복습 정답`, 완료 `1차 정답`
  (완료 카드는 보조 줄에 `1차(전체) 풀이 정답 176/194 · 완료일 …` 을 함께 보여 줍니다).
- 진행도 분모는 그 라운드의 문항 수이고, 카드의 "고유 문항 N개" 는 과목의 중복 제거 문항 수입니다(라운드와 다르면 "이번 라운드 N문항"을 덧붙입니다).
  헤더의 합계(944)는 **과목별 고유 문항 수의 합**이고, 데이터셋 전체 내용키 그룹 수 **938**(두 과목에 걸친 그룹 6개)과는 기준이 다릅니다.
- 회차별 연습·모의고사 진입점은 자리만 둡니다(비활성 버튼 — 다음 단계).

## 연습 화면 계약

`/sessions/{sessionId}` 는 과목 사이클 라운드(`subject`·`review`)와 회차별 연습(`exam_practice`)을 푸는 화면입니다
(모의고사 `exam`·랜덤 `random` 은 이 화면이 아니라고 안내합니다). 흐름은 설계 3.1절 그대로입니다 —
문항·보기 → 보기 선택 → 제출 → **같은 화면에 정오답·해설** → 다음 문항.

- **진행 위치는 서버가 정합니다.** 세션 조회의 `nextSeq` 로 그 문항(`GET …/items/{seq}`)을 열기 때문에
  새로고침·재접속·기기 변경 후에도 같은 자리로 복원됩니다. 헤더는 데스크톱에서 `과목 · 라운드 · 문항 n / m` + `남은 N문항` 을 한 줄로 보여주고,
  375px 처럼 좁은 화면에서는 **`문항 n / m` 을 앞세워 잘리지 않게 두고** 과목·라운드를 아랫줄로 내립니다(리뷰 P2-1).
  이어풀기로 복원했을 때는 "이어서 풀기 — n / m 문항을 마쳤습니다" 안내를 한 번 띄웁니다(홈의 '이어서 풀기'도 같은 세션으로 들어옵니다).
- **지문은 종류별로 다르게 그립니다** — `code`(고정폭·들여쓰기 보존)·`table`(행/열 구분이 보이게 고정폭)·`text`(문단).
  `figure.needed` 문항은 `/figures/...` 이미지를 `alt` 캡션과 함께 보여줍니다(경로는 API 오리진 기준 상대경로).
- **보기별 해설은 기본 접힘(기본안).** 정오답 배지·정답 번호·전체 해설·핵심 개념을 먼저 보여주고,
  보기별 해설은 `보기별 해설 4개 보기` 버튼을 눌러 펼칩니다 — 펼치면 **4개 보기 전부**(정답 보기 포함)의
  보기 텍스트와 정오답 이유를 보여주고 내가 고른 보기에 표시를 붙입니다. 스크린샷을 보고 조정할 항목입니다.
- **제출 응답을 그대로 씁니다** — `PUT …/items/{seq}/answer` 의 `isCorrect`·`answer`·`explanation`·`choicesAnalysis`,
  그리고 진행(`session.nextSeq`)·라운드 종료(`roundResult`)·다음 라운드(`cycle`)를 화면 상태로 삼습니다.
  `elapsedMs` 는 문항이 뜬 뒤 제출까지의 시간입니다.
- **409 는 안내로 끝내고 진행을 막지 않습니다.** 이미 채점된 슬롯에 다른 보기를 보내면 서버 메시지를 그대로 보여주고
  저장된 채점 결과를 다시 불러와 다음 문항으로 갈 수 있게 합니다. 중단(`abandoned`)·종료 세션은 안내와 함께 홈으로 돌려보냅니다.
  같은 보기 재전송은 서버가 멱등(`200`)이라 네트워크 오류 뒤 그대로 다시 눌러도 기록이 늘지 않습니다.
- **라운드 종료** — 마지막 문항을 채점하면 `roundResult`(전체·정답·오답)로 결과를 요약하고,
  `cycle.nextSessionId` 가 있으면 오답 복습 라운드로 들어가는 버튼을, 없으면(오답 0 = 사이클 완료) 완료 안내와 홈 이동을 보여줍니다.
- **오류 상태** — 로딩 스켈레톤, 네트워크·서버 오류(다시 시도·홈으로, 백엔드가 꺼져 있으면 홈과 같은 기동 명령 안내),
  404(없는 세션·문항), 빈 라운드(문항 0개) 안내를 따로 그립니다.

검증(2026-09, 실 DB): 한 과목 사이클을 만들어 브라우저로 문항 2개를 제출하고, 새로고침 복원·홈 이어서 풀기·
176문항 라운드 종료(정답 173·오답 3)·오답 복습 라운드(3문항)·사이클 완료까지 확인한 뒤 검증이 만든 진도 행을 지워 0행으로 되돌렸습니다.
