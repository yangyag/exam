상태: 대화로 보완 중인 초안 — **핵심 흐름(3·4·5장)은 2026-09-12 구현·병합 완료.** 구현 현황은 8장, 남은 의사결정은 9장.  
작성 시작일: 2026-09-11

## 1. 이번 작업의 범위

이번 단계의 산출물은 프론트 구현 설계서 Markdown 파일이다. 화면·사용 흐름·상태·필요한 API 계약을 사용자와 협의해 이 문서에 정리한다.

설계 대화가 끝나더라도 실제 프론트 구현이나 백엔드 수정을 자동으로 시작하지 않는다. 구현은 사용자의 별도 요청으로 진행한다.

아래의 확정 사항과 추가 협의 항목을 구분한다. 현재 문서는 최종 확정본이 아니다.

## 2. 사용 목적

- 정보처리기사 필기 기출문제를 반복해서 풀기 위한 학습 앱이다.
- PC 웹과 출퇴근길의 휴대폰 사용을 고려한다.
- 과목별로 문제를 계속 풀고, 중간에 멈췄다가 이어서 풀 수 있어야 한다.
- 프론트의 학습 흐름을 먼저 정한다. 기존 데이터 구조와 백엔드 API는 필요한 경우 그 흐름에 맞춰 변경할 수 있다.

## 3. 확정한 풀이 방식

| 방식 | 문제 구성 | 채점 시점 |
|---|---|---|
| 과목별 연습 | 선택한 과목의 여러 연도·회차 문제를 섞어서 출제 | 문항별 제출 직후 |
| 회차별 연습 | 연도와 회차를 선택해 해당 기출문제 풀이 | 문항별 제출 직후 |
| 모의고사 | 선택한 회차의 전체 문제 풀이 | 전체 최종 제출 후 |

주된 진입은 과목별 연습이다. 회차별 연습과 모의고사에도 별도로 진입할 수 있다.

### 3.1. 연습의 문항별 흐름

1. 문제와 보기를 읽는다.
2. 보기를 선택한다.
3. 제출 버튼을 누른다.
4. 같은 화면 아래에 정답·오답 여부와 해설을 보여준다.
5. 다음 문제로 이동한다.

데이터에는 문항 전체 해설과 보기별 정오답 이유가 있다. 정답·오답 표시와 전체 해설 표시는 확정 사항이다. 보기별 설명의 기본 노출 범위와 접기·펼치기 방식은 화면을 설계하면서 정한다.

### 3.2. 모의고사

- 문항을 푸는 도중에는 개별 채점 결과와 해설을 공개하지 않는다.
- 전체 최종 제출 후 채점 결과와 해설을 확인한다.
- **제한시간과 타이머는 넣지 않는다.**
- 답안 수정, 문항 번호를 통한 이동, 미응답 문항 처리와 결과 화면의 상세 구성은 추가 협의한다.

## 4. 과목별 학습 사이클

### 4.1. 시작과 진행

문항 수를 선택하는 단계는 두지 않는다. 과목을 선택하면 해당 과목의 여러 연도·회차 문제를 모으고, 같은 내용의 중복 문제를 걸러 순서를 섞어 하나의 문제 목록을 구성한다.

이 목록은 해당 사이클 동안 유지된다. 다음 문제를 요청할 때마다 독립적으로 랜덤 추첨하는 구조가 아니다.

- 사용자는 구성된 목록을 순서대로 계속 푼다.
- 중단 후에는 같은 목록과 풀이 위치에서 이어서 푼다.
- 과목을 이동해도 각 과목의 진행 상황을 유지한다.
- 전체 풀이 중 틀린 문제는 모아두고, 전체 목록을 끝낸 뒤 복습한다.

### 4.2. 오답 복습과 완료

확정한 흐름:

```text
전체 문제 풀이
    ↓
이번 사이클의 오답만 다시 풀이
    ↓
복습에서도 틀린 문제만 모아 다시 풀이
    ↓
모든 문제를 맞힐 때까지 반복
    ↓
사이클 완료
    ↓
사용자가 새로 구성하면 다음 사이클 시작
```

오답 복습에서도 문항별 제출 직후 채점 결과와 해설을 보여준다. 중단 시 복습 중이던 위치를 유지한다.

오답 대상은 해당 사이클의 풀이 결과로 결정한다. 기존 DB의 전체 기간 오답 누계를 그대로 사용하는 것은 이 흐름과 다르다.

처음 전체 풀이에서 오답이 없으면 바로 사이클을 완료할 수 있다. 첫 풀이 성적과 이후 오답 복습 결과는 구분해 남기는 방향으로 설계한다.

## 5. 홈 화면

앱에 들어오면 5개 과목과 과목별 진행 상황을 바로 보여준다.

- 과목명

- 상태에 맞는 시작하기·이어서 풀기·새로 구성하기 동작

## 8. 구현 현황 (2026-09-12)

3장의 확정 흐름과 4장 사이클, 5장 홈이 **모두 구현돼 `main` 에 병합·push** 됐다. 백엔드·DB 변경과 프론트 화면이 함께 들어갔고, 각 작업은 리뷰어의 clean 판정을 거쳐 병합됐다.

| 설계 | 구현 | 근거 |
|---|---|---|
| 3.1 연습의 문항별 흐름 | 연습 화면 `front/app/pages/sessions/[id].vue` — 보기 선택 → 제출 → 정오답·전체 해설·핵심 개념, 보기별 해설은 접기(기본 접힘) | `PUT /api/sessions/{id}/items/{seq}/answer` |
| 3.2 모의고사 | `front/app/pages/exam/[id].vue` — 풀이 중 정답·해설 비노출, 선택은 즉시 저장, 번호 그리드 이동, 제출 확인(미응답 강조), 제출 후 같은 페이지가 결과. **타이머 없음** | 선택 저장 `PUT …/items/{seq}/answer`, 최종 제출 `POST /api/sessions/{id}/submit` |
| 4.1 시작과 진행 | 시작하기 → 서버가 중복 제거·셔플한 고정 목록 생성, `nextSeq` 기반 이어풀기, 과목별 진행 유지 | `study_cycle`·`study_session_item`(`db/003_study_items.sql`), `POST /api/subject-cycles`·`GET /api/subject-cycles/overview` |
| 4.2 오답 복습과 완료 | 마지막 슬롯을 채점할 때 같은 트랜잭션에서 라운드를 닫고, 오답이 있으면 `review` 라운드, 없으면 사이클 완료 | `advance_round_if_complete` |
| 5 홈 화면 | 5과목 카드(상태 4종·진행도·정답 수·진행 막대) + 상태별 동작(시작하기/이어서 풀기/새로 구성) + 진행 중 회차 세션 표시 | `GET /api/subject-cycles/overview`, `GET /api/sessions` |
| 5장의 "별도 진입점" | 회차 선택 화면 `front/app/pages/exams/index.vue` — 13회차 목록, 회차별 연습·모의고사 시작 | `GET /api/exams` |

**검증·기록**

- 백엔드: `pytest` 198개 통과(통합 포함), `--init` 재실행 안전, 진도 테이블은 검증 후 항상 0행 복원.
- 프론트: `npm run build`(타입 0) + `npm run shots` 49컷 전 항목 통과(콘솔 오류 0·가로 잘림 0·클릭 영역 44px·키보드 조작).
- 실 DB 확인: 과목 사이클 완주(전체 → 오답 복습 → 완료), 모의고사 "일부만 선택 → 미응답 다수 제출 → 재제출 멱등".
- 스크린샷(커밋하지 않는 `tmp/`): `tmp/shots-m5/`(홈), `tmp/shots-m6/`(연습), `tmp/shots-f3/`(회차·모의고사·결과).
- 화면별 기본안의 상세는 `front/README.md` 에 적혀 있다.

**구현하지 않은 것** (요청 범위 밖이거나 6장 미정 항목)

- 배포·외부 접속(휴대폰)과 쓰기 토큰(`X-Exam-Token`) — 9장 1번
- 이전 결과(사이클·모의고사) 조회 화면
- 회차별 연습에 오답 반복 적용

- `random`(랜덤 출제) 화면 — API는 남아 있지만 화면 흐름에는 넣지 않았다

6장의 미정 항목 중 "보기별 해설 노출 방식", "모의고사 답안 수정·문항 이동·미응답 처리", "새로고침·재접속 이어풀기"는 기본안으로 구현했고, 아래에서 조정할 수 있다.

각 항목의 "현재 기본안"은 이미 동작하는 값이다. 바꾸기로 정하면 프론트(또는 백엔드) 수정 한 건으로 처리한다.

### 9.1. 확정한 결정 (2026-09-12)

- **1. 배포·외부 접속 — (c) EC2 배포.** 세부(인증 방식·도메인/HTTPS·기존 EC2 재사용 여부·실행 주체)는 협의 중이다. 배포하며 함께 처리할 것: CORS 오리진(`EXAM_CORS_ORIGINS`)에 배포 주소 추가, 프론트의 `X-Exam-Token` 지원(현재 미지원)과 `EXAM_API_TOKEN` 설정, 인증은 **서버단**(예: nginx Basic Auth, Cloudflare Tunnel)에 두고 토큰은 추가 방어로만 쓴다 — 토큰을 프론트 JS 에 넣으면 브라우저 devtools 로 노출된다.
- **2. 연습: 보기별 해설 노출 — (b) 오답일 때 자동 펼침.** 정답이면 지금처럼 접힘을 유지하고, 오답일 때만 보기별 해설을 펼친다. 복습 라운드에도 같은 규칙을 쓴다.
- **3. 모의고사 번호 그리드 — (a) 지금대로.** 데스크톱 펼침·모바일 접힘 유지.
- **4. 모의고사 결과 화면 — (a) 지금대로.** 같은 페이지에서 요약 → 과목별 → 그리드 → 해설 재조회 유지.
- **5. 홈: 진행 중 회차 표시 — (a) 지금대로.** 목록 스캔 유지(세션이 쌓이면 백엔드 필터를 재검토).
- **6. 미응답 문항 점프 — (a) 지금대로.** 번호 그리드 유지.
- **7. 이전 결과 조회 — (a) 과목별 최근 사이클 + 모의고사 목록.** 새 화면으로 만든다. 필요한 API 는 이미 있다(`GET /api/subject-cycles`, `GET /api/sessions`) — 프론트 작업이다.
- **8. 회차별 연습의 순서·필터·오답 반복 — (a) 지금대로.** 번호 순·필터 없음·오답 반복 미적용 유지.
